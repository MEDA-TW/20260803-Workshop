# 以講師成果 Demo 同時提供開場展示與學生啟動備援

Day 3 將公開碩士班資料的可用問答助手定位為講師成果 Demo：課堂一開始用來展示引用、適用年度與問答紀錄的最終效果；學生的本機 App 可執行、但個人資料管線或個人助手無法完成時，可直接開啟它快速完成課程的問答、引用與歷程操作。理想主線仍是學生以自己的資料完成 evidence chain，並在自己的問答頁面累積個人問答紀錄；Demo 不能與學生個人資料混合索引。

學生一旦成功建立自己的 chunks 與向量索引，系統應使用學生資料模式；講師 Demo 不可與學生資料混入同一個索引，也不可自動回退。當學生自己的資料／助手無法完成、但 Streamlit、Python 與 Ollama 可執行時，講師可改以獨立 Demo 完成操作。Streamlit、Python 或 Ollama 本身無法執行時，Demo 也不能在該學生電腦上作為備援。

為了讓學生個人程式或資料壞掉時仍可直接開啟 Demo，starter 另保留與學生個人成果分離的已驗證 Demo 啟動點；它不出現在正常問答介面，也不承擔學生個人資料模式的責任。

Demo 啟動點位於課程根目錄的 `instructor/demo/app.py`；學生只需執行 `python -m streamlit run instructor/demo/app.py`，不複製檔案、不改設定，也不在一般問答頁切換模式。

Demo 沿用介面既有的資料來源顯示即可；課程不評分，不增加失敗標記、復原狀態或學生分類。

所有學生先依學生操作手冊完成自己的資料與助手；只有個人資料流程或個人助手無法完成時，講師或 TA 才引導學生改用 Demo。

Demo 備援完成路徑只要求學生完成有證據問答、查看來源與適用年度、測試另一類問題，並在問答紀錄查看主要主題與來源。Demo 的原始資料、Markdown、chunks、分析與 backlog 可供查看，但不要求學生重做其原本失敗的資料處理步驟。
