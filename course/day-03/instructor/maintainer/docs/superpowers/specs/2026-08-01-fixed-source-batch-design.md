# Day 3 固定來源批次處理設計

## 目的

將新手主流程從「四份資料各重複五段提示詞」改為「一次批次提示詞」。學生不再選擇或貼上網址，而是處理課程指定的四份公開來源：碩士班修業流程、115 學年度研究生手冊、英文畢業門檻與 115-1 行事曆。

## 學生流程

1. 建立工作空間並記錄固定來源、上限與請求間隔；此步不下載。
2. 送出一段批次提示詞。
3. Codex 對四份指定來源逐份執行：確認公開規範、取得一份原始檔、寫入來源紀錄、以 MarkItDown 解析、寫入品質結果。
4. Codex 最後以表格列出四份資料的網址、格式、取得狀態、解析狀態與下一步。
5. 後續整理、RAG、自我測試和改善提示詞直接使用這批結果。

## 失敗處理

- 每一份來源皆先確認公開規範；不允許或無法確認時，不下載。
- 單一來源失敗時，仍寫入失敗原因並繼續下一份指定資料。
- 只有成功取得且品質可用的文字可進入 chunks 與索引。
- 原始檔不覆寫；每次請求維持至少一秒間隔，仍受 20／20 上限限制。

## 教材修改範圍

- `STUDENT_GUIDE.md`：以一段批次提示詞取代 03-1 至 03-5 的重複操作，並保留單一總結驗收。
- `HANDOUTS.md`、`README.md`、練習與 PRD：描述固定四份來源與一次批次處理，不再暗示學生逐份手動貼提示詞。
- 不變更講師 Demo、starter 程式、索引格式或 RAG 問答流程。

## 驗收

- 學生指南不再要求學生貼上網址或把 03-1 至 03-5 重複四次。
- 批次提示詞明確列出依序處理、公開規範、失敗紀錄、不中斷其餘來源、原始檔不覆寫與最終表格。
- 課程提示詞契約、Python 測試與 Markdown 差異檢查通過。
