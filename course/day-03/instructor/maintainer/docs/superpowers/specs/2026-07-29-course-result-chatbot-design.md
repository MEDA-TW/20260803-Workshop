# Day 03 課程成果聊天助手設計

## 目的

把目前以課程說明為主的 Streamlit 原型，改成學生在一天課程結束時可產出的本機文件問答助手。首頁專注問答；問答紀錄和講師展示不干擾一般使用者。

## 使用者與成功條件

- 學生：開啟後立即能問問題、看見簡短回答和可回查來源；不必理解 chunks、測試表或資料夾結構。
- 講師／TA：可開啟本機後台，確認每題的問題、狀態、來源、相似度和耗時。
- 成功條件：首頁只呈現必要問答資訊；每個有根據的答案顯示主要來源；資料外問題回覆 `insufficient_evidence`；問答紀錄不會消失；既有 HTML、PDF、DOCX RAG 與引用契約維持可用。

## 採用方案

採用單一 `starter/rag/app.py` 加上側欄頁面切換，不建立 Streamlit `pages/` 資料夾。

理由：學生只需啟動一個檔案，仍能得到清楚的「問答／問答紀錄／講師 Demo」分頁；比多檔案架構更容易在課堂中理解與修改。

## 介面

### 1. 問答（預設首頁）

- 品牌列：`雲科大技職所｜文件問答助手`，副標說明只根據本次蒐集的公開文件回答。
- 對話區：原生 Streamlit chat message，使用者與助手訊息清楚區隔。
- 第一則回答前：三個建議問題按鈕，協助新手立即測試。
- 助手回答後：先顯示簡短回答，再顯示主要來源（段落名稱、文件類型、相似度）；完整三筆檢索來源維持折疊。
- 底部：固定 `st.chat_input`。
- 不顯示：chunk 數、測試表、manifest 路徑、改善 backlog、技術健康檢查細節。

### 2. 問答紀錄（本機後台）

- 側欄進入，不作為首頁內容。
- 上方顯示筆數、已回答數、資料不足數與平均耗時。
- 每筆紀錄以可展開卡片呈現問題、回答、回答狀態、耗時、主要來源與完整來源。
- 提供「清除本機紀錄」按鈕前，必須先要求使用者確認；本次改版不預設加入清除功能。

### 3. 講師 Demo

- 側欄進入，維持結業成果展示。
- 收合技術細節；預設只顯示成果摘要、建議展示流程與五類測試結果。
- 保留原始 manifest、分析與 backlog 的檔案路徑，供講師需要時查看。

## 資料與回答流程

1. 載入學生 index；若無則載入 sample index。
2. 對新問題產生 query embedding、選取最多三筆候選來源。
3. 表單名稱直接命中問題時，只將同名文件的直接證據送入回答模型，避免相近表單互相污染；完整候選仍保存到紀錄。
4. 有足夠證據時由 Qwen 產生短回答；不足時不呼叫回答模型。
5. 所有結果寫入本機 `feedback/query_log.jsonl`。

## 錯誤與速度

- 回答期間顯示「檢索資料」與「組織回答」的狀態；完成後顯示耗時。
- Ollama 或模型不可用時，首頁顯示簡短修復提示；詳細模型檢查移到側欄。
- 因裝置無法同時常駐兩個模型，第一題可能較慢；本次不改變向量 RAG 架構或新增模型下載。

## 驗收

1. 首頁不出現課程結果表、manifest 路徑或測試列表。
2. 一般問題可完成一問一答，底部輸入框可用，主要來源可見。
3. PDF／DOCX 期限問題引用同名文件的期限 chunk，並正確回答「博士生修課計畫」的第一學期截止時間。
4. 後台可看到實際問答紀錄的狀態、耗時與來源。
5. `python -m py_compile starter/rag/app.py`、提示詞契約檢查與 Streamlit 本機互動測試通過。
