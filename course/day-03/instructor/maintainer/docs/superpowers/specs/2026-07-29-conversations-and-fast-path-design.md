# Day 03 對話歷程與快速回答設計

## 目的

把課程成果聊天助手從單題紀錄，改成可進行多輪問答的對話介面。學生可開啟新對話、以左右訊息泡泡閱讀問答；講師可在本機後台用表格回看每一串對話。明確文件問題優先快速回覆，複雜問題才交由 Qwen 生成短答。

## 成功條件

- 使用者訊息顯示在右側，助手訊息顯示在左側；輸入欄維持在頁面底部。
- 只有按下「＋開新對話」才產生新的對話紀錄；同一串的多輪問答共用一個 `conversation_id`。
- 問答紀錄首頁是一列一串對話的表格，可展開查看該串每一題、回答、引用與耗時。
- 有明確來源證據的問題不等待 Qwen；資料不足時仍回覆 `insufficient_evidence`，不猜測。
- 舊有 JSONL 單題紀錄可被讀取，不遺失，也不需要人工轉檔。

## 介面

### 問答頁

- 側欄的「＋開新對話」按鈕建立新的 UUID，重置畫面中的暫存訊息，並設定新的開始時間。
- 當前對話標題預設為第一題前 24 個字；無題目時顯示「新對話」。
- 訊息以自訂 CSS 將使用者泡泡靠右、助手泡泡靠左；助手回答下方保留主要來源、完整引用摺疊區、回答類型和耗時。
- 回答類型為「快速回答」或「模型整理」：前者直接從單一、明確匹配且足夠相似的文件 chunk 摘取對問題最相關的內容；後者維持既有檢索後呼叫 Qwen 的短答流程。

### 問答紀錄頁

- 頂端指標以對話為主：對話數、總問題、已回答問題、平均秒數。
- 表格每一列是一個 conversation，欄位為開始時間、對話標題、問答數、已回答數、平均秒數。
- 使用者選取或展開某列後，依輪次顯示完整問答；每一題保留狀態、回答模式、主要來源及完整 chunk ID。
- 未帶 `conversation_id` 的舊資料一律視為各自獨立的一輪舊對話；標題取其問題文字，確保既有測試與展示紀錄仍能閱讀。

### 講師 Demo

- 更新成展示兩至三輪同一對話、快速回答與模型整理的差別，以及在後台從一列展開完整對話。
- 仍維持結業作品的精簡介紹，不把索引、manifest 或測試結構放到一般問答首頁。

## 資料契約

每次寫入 `feedback/query_log.jsonl` 的新紀錄新增：

| 欄位 | 說明 |
| --- | --- |
| `conversation_id` | 同一串問答共用的 UUID |
| `conversation_started_at` | 按下開新對話時的 UTC 時間 |
| `conversation_title` | 第一題衍生的短標題 |
| `turn_index` | 該串從 1 起算的提問輪次 |
| `answer_mode` | `fast_evidence`、`model_summary` 或 `insufficient_evidence` |

既有 `query_id`、`asked_at`、`question`、`answer`、`answer_status`、`cited_chunk_ids`、`retrieval_scores` 和 `latency_seconds` 維持不變。JSONL 仍是單一事實來源，後台載入時才依 `conversation_id` 分組。

## 快速回答邊界

1. 先建立 query embedding，取前三筆候選 chunk。
2. 僅在問題明確提到某一份表單或文件名稱、同名 chunk 為最高候選、相似度達現有門檻，且該 chunk 可擷取非空證據文字時，使用快速回答。
3. 快速回答只呈現來源中可支持的句子，不補充未寫明的規定；無法安全擷取時改走模型整理。
4. 模型整理沿用 `answer_evidence`，避免同類表單的期限互相污染。
5. 任一候選低於門檻時不呼叫 Qwen，回覆 `insufficient_evidence`。

這保留本機向量 RAG、公開來源與引用契約。模型維持 `keep_alive=0`，不要求學生電腦同時常駐 embedding 與回答模型。

## 錯誤與驗證

- Ollama 或模型不可用時，訊息列以助手錯誤泡泡呈現可操作的修復提示，且不新增偽造的成功紀錄。
- 快速回答和模型整理都記錄實際耗時；後台平均值包含兩者，方便課堂比較。
- 為 helper 新增測試：對話分組、舊紀錄相容、標題與輪次、快速回答判定與資料不足分支。
- 執行 Python 單元測試、編譯檢查、提示詞契約檢查和 Streamlit 瀏覽器互動測試；至少驗證一個快速回答、一個模型整理、一個新對話與一個舊紀錄分組案例。

## 非目標

- 不新增帳號、雲端資料庫、跨裝置同步或多人共用後台。
- 不下載新的 Ollama 模型，也不讓兩個模型同時常駐。
- 不改變公開資料來源邊界或既有 HTML、PDF、DOCX 解析流程。
