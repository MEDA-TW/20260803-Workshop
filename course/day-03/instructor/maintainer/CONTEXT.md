# Day 3 課程設計語彙

本文件定義 Day 3 講師與維護者討論教材結構時使用的固定術語；學生不需要閱讀。

## Day 3 目前定位

**上午｜論文摘要探索與主分類分析**：以 `text-analysis-demo/` 的 255 篇講師提供摘要為分析單位。流程是關鍵詞／方法線索探索 → 候選主分類與變更建議 → 研究者確認 → 試編碼與全量編碼 → Word 比較報告。探索結果是分類形成的過程證據；最後報告只保留確認後的主分類。

**下午｜校務文件 RAG**：以 `rag-demo/` 的固定校務文件完成 MarkItDown 解析、品質檢查、chunks、索引與有引用的本機問答助手。下午的 RAG 工具鏈不屬於上午的必要環境。

**雙軌證據規則**：上午的結論至少回連 `corpus_id`、`source_url` 與摘要原文；下午的回答回連 chunk、文件來源與適用時間。兩段都要把原文證據、AI 初步結果與人工確認／限制分開。

## Language

**學生操作手冊**：
學生依上午與下午資料夾分別閱讀的課程文件，包含提示詞、完成證據與卡關處理。
_Avoid_: 提示詞資料夾、練習檔集合

**學生 rag-demo**：
每位學生在課程開始時取得的資料與程式建置起點；保留空白 `rag/app.py`、索引腳本與資料夾結構，學生在資料完成後用 Codex 建立自己的 Streamlit RAG。
_Avoid_: 救援包、完成品範例、預先完成的學生介面

**講師成果 Demo**：
講師於開場展示與失敗備援的可用問答助手，以公開碩士班資料呈現帶來源與年度的最終效果；學生個人實作失敗、但本機 App 可執行時，可用它快速完成課程的問答、引用與歷程操作。
_Avoid_: 學生自己的資料成果、與個人資料混合索引

**獨立 Demo 啟動點**：
課程根目錄 `instructor/demo/app.py` 的已驗證啟動入口；只在學生個人程式或資料無法使用、但本機環境仍能執行時，以 `python -m streamlit run instructor/demo/app.py` 使用。
_Avoid_: 正常資料模式、學生與講師資料的混合索引

**Demo 備援完成路徑**：
學生改用講師成果 Demo 後的最小操作：完成有證據問答、檢視來源與適用年度、測試另一類問題，並在問答紀錄查看主要主題與來源；可查看既有資料鏈，但不重做造成失敗的資料處理步驟。
_Avoid_: 重跑失敗流程、個人資料成果

**學生資料模式**：
學生完成自己的 chunks 與索引後自動啟用的問答資料來源；它會取代講師成果 Demo，作為學生證據展示與改善的唯一依據。
_Avoid_: 與講師 Demo 混合索引、手動選擇語料

**個人問答紀錄**：
學生以自己的問答助手提問時，在個人問答頁面累積的歷程；它用於回顧主要主題、來源與改善，不應混入講師成果 Demo 的操作。
_Avoid_: 講師 Demo 紀錄、全班集中紀錄

**RAG 接線與測試**：
學生先建立自己的 `ready_for_analysis` chunks 與索引，再用 Codex 從空白建立 `rag/app.py`，完成檢索、四類問答、自我歷程檢查與改善 backlog。
_Avoid_: 預先完成的學生 RAG、從零實作向量演算法

**個人 Day 3 專案**：
學生由講師提供的 GitHub Template 建立的 private repository，承載自己的資料、問答歷程與 commit；不包含整份工作坊教材。
_Avoid_: 在課程教材 repo 內建立 my-project、公開部署資料成果

**課前環境完成**：
下午學生在到課前安裝 Codex、Python、Ollama、指定模型與 MarkItDown MCP；上午只需 Codex Desktop 與講師提供的摘要資料。課堂開始後先分別確認兩個資料包，不把下午環境問題當成上午分析的前置條件。
_Avoid_: 課堂開始後才下載模型

**Demo 備援切換**：
學生先建立自己的資料與助手；個人資料或助手無法完成、但 Python、Streamlit 與 Ollama 仍可執行時，改用獨立講師成果 Demo 完成問答、引用與問答紀錄操作。Demo 不與學生資料混用，也不能處理本機環境本身無法啟動的問題。
_Avoid_: 無限排查網站或下載問題、把 Demo 資料混進個人專案

**證據展示**：
Day 3 的雙軌收尾畫面：上午展示只保留確認後主分類的 Word 比較報告與一筆摘要證據；下午展示一題有引用的問答、該題的本機問答歷程，以及一項可回查的改善 backlog。
_Avoid_: 只展示聊天介面、公開部署網址

**現場自我展示**：
學生在課堂以自己的電腦完成證據展示，講師與 TA 巡迴確認；不蒐集連結或原始資料、不計分、不要求公開成果。
_Avoid_: 作業繳交、公開部署、集中蒐集問答紀錄

**健康檢查 sample chunks**：
rag-demo 隨附的極小公開 chunks，只用於索引腳本與資料格式健康檢查；學生建立自己的介面後仍不得將它當成最後證據展示的資料來源。
_Avoid_: 最終語料、講師成果 Demo 資料、預先完成介面

**證據鏈**：
從資料範圍、原始檔、Markdown、chunks，到帶有 provenance 的問答、歷程與改善項目的可回查關係。
_Avoid_: 單純 chatbot 成果

**核心問答資料**：
學生個人助手最低必備的三類公開資料：碩士班修課與畢業學分規定、英文畢業門檻及其適用年度、至少一份相關流程或表單；資料只取自雲科大技職所與語言中心官方主機。校務行事曆可取自教務處官方主機。
_Avoid_: 與修課無關的隨機網頁、只為湊文件數的語料

**動態校務資料**：
可選擇納入的校務行事曆與公告，用來回答申請、繳交或活動日期；每個回答必須說明適用學年度或公告日期，不能由舊資料推測新日期。
_Avoid_: 無年份日期、把舊公告當成最新規定

**四類核心自我測試**：
學生助手的固定測試：修課與畢業學分、英文門檻與年度、流程或表單、校務日期；所有回答附來源，英文與日期題另附適用年度或公告日期。
_Avoid_: 無關的湊數問題、沒有來源的聊天展示
