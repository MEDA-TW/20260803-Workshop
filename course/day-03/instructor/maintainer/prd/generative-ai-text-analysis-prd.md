# Day 3 雙軌文本分析課程 PRD

## 目標

Day 3 分成上午與下午兩個獨立模組，共同練習「讓生成式 AI 協助整理文本，但保留可回查證據」：

- 上午「論文摘要探索與主分類分析」：以北科大與雲科大技職所 255 篇博碩士論文摘要為資料，先探索關鍵詞與方法線索，再由研究者確認主分類，完成兩校與學位別的描述性比較，最後產出 Word 報告。
- 下午「校務文件 RAG」：以講師提供的固定校務文件完成文字轉換、品質檢查、索引與有引用的本機問答助手。

上午的主分類不是一開始就視為不可變更的結果；它要由摘要探索提出候選，再經研究者確認。最後 Word 報告只呈現確認後的主分類；探索統計與變更紀錄留在分析衍生檔作為方法證據。

## 使用者與資料邊界

- 課程學員：以 Codex Desktop 依兩個資料夾內的提示詞完成分析，不要求手寫程式或使用 Git。
- 講師／TA：確認資料範圍、主分類決策、人工抽查與成果展示，不代替學員做未經確認的研究判讀。
- 上午只使用 `text-analysis-demo/data/thesis_abstracts_110_114.jsonl` 與 `data/source_manifest.json`；不可修改、下載全文或新增網路來源。
- 下午只使用 `rag-demo/` 內講師提供的固定文件與來源 manifest；學生不自行找網址或爬取。

## 上午功能需求｜論文摘要探索與主分類分析

1. 載入並檢查摘要筆數、欄位、唯一識別碼、學校與學位別；缺漏要列出，不得猜補。
2. 從摘要探索關鍵詞與方法線索。每筆探索結果保留 `corpus_id`、`source_url`、摘要證據與探索欄位；方法線索可複選，不當成互斥統計。
3. 根據探索結果提出主分類候選與變更建議，逐項說明保留、增加、合併、刪除或不變更的理由，並附摘要證據。
4. 研究者確認主分類前不得進入試編碼與全量編碼；若無實質變更，必須記錄「探索後主分類未變更」。
5. 以確認後主分類完成 8 篇試編碼與全量 AI 初步編碼；原文證據、AI 編碼與人工確認欄位分開。
6. 產出兩校全體與碩士／博士分層的篇數、比例、支持證據、限制與缺漏檢查；不可解讀為品質高低或因果關係。
7. 產出 `analysis/comparison_report.docx`。最後 Word 報告只保留確認後的主分類，不放關鍵詞／方法線索探索統計表或圖；探索與變更紀錄保留在 `analysis/`。

## 下午功能需求｜校務文件 RAG

1. 健康檢查 Python、Ollama、`qwen2.5:3b`、`nomic-embed-text-v2-moe`、Streamlit 與 MarkItDown MCP。
2. 對固定 raw 與 manifest 進行 MarkItDown 轉換與品質檢查；raw 與 manifest 不可修改。
3. 只將 `ready_for_analysis` chunks 建立本機向量索引。
4. 以 Codex 建立 Streamlit 問答與問答紀錄；每題顯示來源段落、URL、文件名稱與適用時間。
5. 證據不足時輸出 `insufficient_evidence`，不可讓模型補造答案；每次自我測試追加本機 JSONL 紀錄並可形成改善 backlog。

## 非目標與安全界線

- 不下載上午論文全文、不新增網路來源、不修改講師提供的 raw data 或 manifest。
- 不將摘要中未明確寫出的內容補成研究方法、研究對象或結論；資訊不足填 `無法判定`。
- 不把探索詞頻、方法線索或 AI 初步編碼誤稱為研究者確認後的主分類。
- 不把兩校差異解讀為學校／論文品質高低或因果關係。
- 下午不處理登入後資料、跨主機內容、正式上線服務、公開部署或真人使用者研究。

## 完成條件

### 上午

1. 探索 CSV、方法線索 CSV、主分類 JSON 與 change log 可回連摘要證據。
2. 全量編碼一篇摘要一列，包含 codebook version、AI 初步狀態與人工確認欄位。
3. Word 報告存在且只使用最後確認的主分類，同時呈現篇數與比例並檢查碩士／博士。
4. 回報缺漏、無法判定與仍需人工確認處。

### 下午

1. Markdown、品質報告、chunks 與索引均保留 provenance。
2. 問答有引用；證據不足時停止回答；英文與日期題顯示適用年度或公告日期。
3. 每題自我測試與改善 backlog 可回連 `query_id`。
