# Day 3｜依序貼給 Codex 的提示詞

請依照順序使用這五段提示詞。每完成一段、看過結果後，再貼下一段，不要跳過前面的檢查。

## 提示詞 1｜先確認工具

請複製下面這段文字貼給 Codex：

```text
我已開啟 Day 3 的 `rag-demo/` 工作空間。

請先幫我確認這個課程需要的工具是否可以使用：

1. Python
2. Streamlit
3. Ollama
4. 目前 Codex task 的 MarkItDown MCP
5. `qwen2.5:3b`
6. `nomic-embed-text-v2-moe`

請不要下載資料、不要安裝新模型、不要建立新專題資料夾，也不要修改任何專案檔案。

如果工具已安裝但目前沒有啟動，請清楚區分「已安裝」和「目前可以使用」。

完成後請用簡短表格回報：

| 工具或模型 | 結果 | 檢查到的證據 | 是否需要講師協助 |
|---|---|---|---|
```

## 提示詞 2｜把文件轉成 Markdown 並檢查品質

請複製下面這段文字貼給 Codex：

```text
請只處理 `data/manifests/crawl_manifest.jsonl` 列出的講師提供原始文件。

請使用目前可以使用的 MarkItDown MCP，把每份本機原始文件轉成容易閱讀與搜尋的 Markdown，並寫入 `data/markdown/`。

請遵守以下規則：

- 不要修改 `data/raw/` 裡的原始文件。
- 不要修改 `data/manifests/` 裡的來源紀錄。
- 不要新增網址、下載其他資料或自行尋找新文件。
- 每份 Markdown 都要保留文件名稱、來源網址與取得時間等來源資訊。
- 每份文件都要在檔案中加入簡短的品質檢查結果。

請檢查：

- 一般文字是否可以閱讀與搜尋。
- 表格的欄位是否還能正確對應。
- 月曆中的日期、星期、週次與辦理事項是否還能一一對應。
- 流程圖中的步驟與分支是否仍能理解。
- 掃描文件是否真的有可讀文字。

品質結果請分成：

- 可分析
- 可分析，但某些段落需要人工查看
- 需要人工查看

如果只有部分表格或流程圖無法可靠還原，請只標記那些段落，不要直接排除整份文件。如果主要內容都無法確認，才將整份文件標記為需要人工查看。

如果 Markdown 的表格欄位排列不清楚，但原始文件是可讀取的 HTML、DOCX 或 PDF，請以唯讀方式對照該份本機原始文件，確認需要使用的段落與欄位是否能可靠對應。對照後可以可靠確認的段落，品質結果可標為「可分析」，並在品質檢查中記錄核對的原始檔案位置；仍無法確認的段落，才標記為需要人工查看。不要因為整份文件有部分問題，就排除其中已確認的段落。

完成後請用表格回報：

| 文件 | 原始格式 | Markdown 是否建立 | 品質結果 | 未納入的段落 | 下一步 |
|---|---|---|---|---|---|
```

## 提示詞 3｜建立校務文件分析表

請複製下面這段文字貼給 Codex：

```text
請只使用前一步品質檢查通過的 Markdown，建立：

`analysis/document_analysis.md`

請把文件內容整理成可以回查來源的分析表。

每一列只整理一個清楚的主題或規定，不要把整份文件濃縮成一列。可以整理的主題例如：

- 畢業學分
- 修課規定
- 指導教授
- 論文計畫
- 學位考試
- 表單或申請流程
- 英文畢業門檻
- 校務日期

表格必須有以下欄位：

- 文件
- 文件明確寫了什麼
- 適用對象與年度
- 學生需要採取的行動
- AI 摘要或分類
- 不確定處
- 來源段落

請特別注意：

- 「文件明確寫了什麼」只整理來源文字。
- 「AI 摘要或分類」才可以寫整理後的解讀。
- 如果不同段落的規定不一致，請把差異寫出來，不要自行選一個答案。
- 如果來源沒有寫清楚年度、身分、期限或例外，請在「不確定處」標明。
- 不要使用品質檢查未通過的文件或段落。
- 不要修改原始文件。

完成後請回報：

| 文件 | 整理出的項目數 | 未納入內容 | 原因 |
|---|---:|---|---|
```

## 提示詞 4｜切成可搜尋的小段落並建立索引

請複製下面這段文字貼給 Codex：

```text
請只使用品質檢查通過的 Markdown，建立可以搜尋與引用的小段落。

這裡的小段落，是指可以單獨回答一個問題的文字。例如：

- 「畢業至少需要幾學分」是一段。
- 「英文畢業門檻」是一段。
- 「論文口試申請期限」是一段。
- 「研究生修課計畫表」是一段。

請不要把分析表的一列直接當成一個小段落，也不要把整份文件放成一段。

每個小段落請：

- 只處理一個主要主題。
- 盡量包含一至三個相鄰段落。
- 保留文件名稱、原始網址、取得時間、段落標題與來源文字。
- 加上一個不重複的小段落編號，方便之後引用。
- 標明主題，例如畢業學分、英文門檻、流程或表單、校務日期。
- 如果內容有年度、身分或版本限制，請一起保留。
- 如果內容不確定，請標明不確定原因。
- 不要納入品質檢查未通過的段落。
- 文件整體標為「可分析，但某些段落需要人工查看」時，只排除被標記的段落；已完成人工核對並標為「可分析」的段落可以建立小段落。
- 表格若只有部分欄位能可靠對應，只納入已確認的欄位與列，並保留人工核對位置與適用限制。
- 每個小段落都必須能直接支持一個具體問題；同一主題但不能直接回答該問題的文字不要放進同一段。
- 數字、日期、表單名稱與適用對象應放在同一個小段落，讓之後能檢查問題與來源是否直接對應。
- 不要為了湊主題而猜測或補寫資料。

請把結果寫入 `data/processed/`，檔名請以 `.chunks.jsonl` 結尾，例如：

`data/processed/student.chunks.jsonl`

JSONL 的意思是「每一行放一筆資料」。請確保每一行都能被讀取。

接著請在課程環境中執行既有的：

`python scripts/build_index.py`

建立：

`data/processed/vector_index.jsonl`

如果目前沒有 `python` 這個指令，請使用課程虛擬環境的 Python 執行同一支腳本。

完成前請檢查：

- chunks 每一行都能讀取。
- 向量索引每一行都能讀取。
- 每段都有完整的文件、來源、時間、段落標題與文字。
- 每個小段落都有不重複的編號。
- chunks 數量與向量索引數量一致。
- 四類主題都有涵蓋；如果某一類沒有可靠來源，請明確說明，不要猜測。
- 行事曆或其他需要人工查看的內容沒有被放入索引。

完成後請用表格回報：

| 文件 | 切成幾段 | 涵蓋的主題 | 未納入內容 | 原因 |
|---|---:|---|---|---|
```

## 提示詞 5｜建立可引用的問答助手

請複製下面這段文字貼給 Codex：

```text
請從空白建立 `rag/app.py`，使用 Streamlit 完成一個「校務文件問答助手」。

請只讀取學生自己建立的：

`data/processed/vector_index.jsonl`

如果這個索引不存在，請在畫面上顯示：

「請先完成提示詞 4」

不要載入講師範例資料，也不要自行建立替代資料。

介面請包含：

- 使用者的訊息顯示在右側。
- 助理的訊息顯示在左側。
- 底部有問題輸入框。
- 側欄有「＋ 開新對話」。
- 有「問答」與「問答紀錄」兩個畫面。
- 問答紀錄用表格顯示主要主題、題數、狀態與平均回應時間。

回答時請遵守：

- 每次最多使用三個相關小段落。
- 回答只能根據檢索到的文件內容。
- 每個有根據的回答都要顯示文件名稱、來源段落、原始網址與取得時間。
- 如果問題缺少年度、身分或版本，先以索引中與問題最相關且取得時間較新的來源回答，不要一律要求使用者補充；回答中要清楚標示來源的適用年度、身分、版本與不確定處。這裡的「最新」是依 `crawled_at` 判斷來源取得時間，不等於自動判定法規生效年度。
- 如果不同來源或不同年度的規定不一致，請並列差異，不要自行選一個答案。
- 回答前先確認檢索段落是否直接包含問題所需的主題、對象與關鍵事實；只有相似詞或同屬校務文件，不算直接證據。
- 只引用真正支持答案的段落，不要為了湊滿三段而引用相關但不能回答問題的段落；如果一段已足夠，使用一段即可。
- 如果來源沒有直接支持答案，顯示：
  「資料不足，無法根據目前來源回答」
- 不要使用常識猜測。
- 不要把文件中的不確定內容說成確定規定。
- 如果模型回答不足，但來源文字已直接支持答案，請顯示來源文字與引用，不要讓模型自行補寫。
- 如果英文門檻段落已經人工核對，回答「英文畢業門檻是多少」時要列出來源中的主要選項與數值，並分開說明 111 學年度前校訂規定與 112 學年度後系所自訂的限制；若只有適用年度說明而沒有可靠數值，不要自行補出分數。
- 對日期、分數、學分與資格條件，必須引用包含該確切數值或條件的來源文字。
- 請另外測試範圍外問題，例如「學校附近哪裡有好吃的便當」；不得使用最相似的校務段落補答，必須顯示資料不足。
- 不要使用範例資料或其他課程的資料。

請把每次問題、回答、引用、狀態與四題測試結果寫入：

`feedback/query_log.jsonl`

最後請執行：

`python -m streamlit run rag/app.py`

如果目前沒有 `python` 這個指令，請使用課程虛擬環境的 Python 執行 Streamlit。

請測試以下四類問題：

1. `碩士班畢業門檻需要修多少學分`
2. `英文畢業門檻是多少`
3. `研究生修課計畫表要怎麼申請`
4. `學位考試申請截止日是哪一天`

每一題都要檢查：

- 回答是否有來源。
- 即使問題沒有提供年度或身分，是否優先使用較新的相關來源並揭露來源適用範圍。
- 英文門檻若有人工核對數值，是否列出主要選項、數值與年度限制。
- 若來源不足，是否正確顯示資料不足。
- 問答紀錄是否成功寫入 JSONL。

完成後請回報：

| 測試主題 | 結果 | 是否有引用 | 是否需要補充資料 |
|---|---|---|---|
```
