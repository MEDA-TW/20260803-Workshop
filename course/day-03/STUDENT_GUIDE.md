# Day 3 學生指南｜從公開文本到可引用問答

你今天只重複一個循環：

```text
界定資料 → 留下證據 → 問答查證 → 記錄改善
```

卡住超過五分鐘：保留完整錯誤文字，找講師或 TA；不要自行換模型、MCP server 或資料來源。

## 01｜課前與開場健康檢查

你已在 Day 1 建立自己的 **private** 練習 repo。請用 Codex Desktop 開啟它。

### 先進入正確資料夾

若 Terminal 提示字尾是 `day-03 %`，請先執行：

```bash
cd starter
pwd
ls requirements.txt rag
```

畫面應顯示 `requirements.txt` 與 `rag`，且提示字尾變成 `day-03/starter %`。**後續所有安裝與啟動指令都只能在這個資料夾執行。** 若看不到這兩個項目，先通知講師，不要在 `day-03/` 根目錄建立 `.venv` 或自行 Fork／另建 repo。

課前請依序完成以下三項安裝。每一項成功後，再進行下一項。

### 1｜安裝 Ollama 與兩個模型

1. 前往 [Ollama 下載頁](https://ollama.com/download) 安裝 Ollama；macOS 安裝後請開啟 App 一次。
2. 回到 Terminal，依序執行：

```bash
ollama pull qwen2.5:3b
ollama pull nomic-embed-text-v2-moe
ollama list
```

3. `ollama list` 必須同時看到 `qwen2.5:3b` 與 `nomic-embed-text-v2-moe`。前者負責回答，後者只用於建立搜尋索引。

### 2｜建立 Python／Streamlit 環境

在 Day 3 starter 根目錄執行：

```bash
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

需要 Python 3.10 以上。這會安裝 Streamlit 與 Ollama 的 Python 套件。若 `python3` 找不到，或安裝失敗，保留完整錯誤文字交給講師；不要改用別的 Python 或套件版本。

### 3｜設定 MarkItDown MCP

先開啟 **Codex Desktop**，建立新的 task，在訊息輸入框輸入：

```text
/mcp
```

在清單中確認 `markitdown` 顯示為可用／enabled。Day 3 不要求安裝 Codex CLI，因此不要在 Terminal 執行 `codex mcp list`。若沒有看到 `markitdown`，或狀態不是 `enabled`，保留畫面或錯誤文字找講師；不要自行安裝其他 MCP server。講師完成設定後，完全關閉並重新開啟 Codex，建立新的 task，再輸入 `/mcp` 確認。

### 4｜工具健康檢查

```bash
ollama list
python -c "import ollama, streamlit; print('Python、Ollama、Streamlit 套件可用')"
```

健康檢查時先在 Codex Desktop 輸入 `/mcp` 確認 MarkItDown。此時還沒有學生版問答介面，因此**不要執行** `python -m streamlit run rag/app.py`，也不需用 sample-data 問問題。完成資料與索引後，你才會在第 05 節用 Codex 從空白建立自己的介面。

## 03｜爬取、解析與品質檢查

四份來源已固定，所以只需貼上下面一段批次提示詞一次；不要自行新增網址。Codex 會在背景逐份處理，並在最後一次列出全部結果。

**提示詞 03｜批次取得、解析與品質檢查**

> 依剛才記錄的四份課程指定資料，一次依序處理全部資料。所有新檔案只能寫入目前的 `data/`、`analysis/` 或 `feedback/`，不要建立新的專題資料夾。每份都先逐份確認公開規範；可以繼續才取得並保留原始檔，原始檔必須保留不動且不覆寫。每處理一份資料，就在 `data/manifests/crawl_manifest.jsonl` 留下一筆來源紀錄，讓我日後能知道：這是什麼資料、從哪裡取得、是什麼格式、原始檔叫什麼、何時取得、存放位置，以及目前是否成功；若失敗，清楚留下原因。直接使用目前已啟用的 MarkItDown MCP 解析本機原始檔，不要安裝、啟動或另外建立 MCP server，也不要建立收集、重試或解析用的 Python 腳本。把可閱讀、可搜尋的文字與品質結果寫入 `data/markdown/`。不能繼續或失敗時，記錄失敗原因後繼續處理下一份指定資料。不要新增網址，兩次請求至少相隔 1 秒，且不得超過 20 個網頁和 20 份附件。最後用表格列出每份資料的網址、格式、取得、解析與品質結果，以及下一步。

你應該看到的結果：一張四列的結果表格。成功且可分析的資料涵蓋修課／畢業學分、英文畢業門檻與適用年度、流程或表單、校務行事曆／公告；個別來源失敗時應有失敗原因，但不會中斷其他指定來源。若整批資料流程卡住，但 Python／Streamlit／Ollama 可正常啟動，講師會提供獨立成果 Demo 供你完成問答、引用與問答紀錄操作；你的資料仍保留在個人專案內。

## 04｜整理與 AI 分析

**提示詞 04-1｜選取可分析文件**

> 請列出目前品質檢查通過、適合進一步整理的文件；不要把需要人工查看的文件算進來，也不要改動原始資料。

**提示詞 04-2｜切成可引用小段落**

> 請把剛才通過檢查的文件，依章節切成適合被問答系統搜尋的小段落。每段都要能回到原始來源與取得時間，並將結果存成 `data/processed/chunks.jsonl`。完成後告訴我每份文件切成幾段。

**提示詞 04-3｜建立分析表**

> 請整理這些段落的重點，但把「文件明確寫了什麼」和「你的摘要或分類」分開呈現。不要把你的推論當成原文規定。

你應該看到的結果：至少有三段可回到來源的內容，分析表也清楚區分文件原文與 AI 摘要。接著執行 `python scripts/build_index.py` 建立搜尋索引；只有資料新增或改動時才需要重跑。

## 05｜用 Codex 從空白建立 Streamlit RAG 問答助手

現在你的資料與索引已完成。以下四段提示詞依序貼到同一個 Codex task；每一段完成並能執行後，才貼下一段。

**提示詞 05-1｜建立最小 Streamlit 介面**

> 請從空白建立 `rag/app.py`，不要使用預先完成的問答介面。用這堂課已安裝的 Streamlit 建立「雲科大技職所｜碩士班文件問答助手」頁面，設定頁面標題，在頁面底部加入可輸入問題的輸入框。先只顯示使用者輸入的問題與「介面已建立，下一步接上資料」的暫時回覆；不要讀取資料或呼叫 Ollama。完成後執行 `python -m streamlit run rag/app.py`，確認頁面可開啟。

**提示詞 05-2｜完成聊天互動與新對話**

> 請在我剛建立的 `rag/app.py` 加入聊天互動，不要重寫資料處理檔案。使用 Streamlit 的聊天元件，讓使用者問題顯示在右側、助理暫時回覆顯示在左側；輸入框維持在底部。以側欄的「＋ 開新對話」按鈕清空目前對話。完成後重新執行 `python -m streamlit run rag/app.py`，確認可以連續問兩題並開新對話。

**提示詞 05-3｜接上我的資料、引用與問答紀錄**

> 請在我剛建立的 `rag/app.py` 接上我的 RAG 資料，不要改動原始檔。讀取 `data/processed/vector_index.jsonl`；若找不到它，清楚提示我先執行 `python scripts/build_index.py`。每次問題只用 `nomic-embed-text-v2-moe` 建立查詢向量，從最多三個相關小段落中找答案，再用 `qwen2.5:3b` 只根據這些來源回答。回答前要先確認引用內容直接支持答案；不得因為段落相似、卻出現不相關的日期、數字或名詞就拿來回答。對日期、數字或期限等精確事實，除了向量相似度，也要用問題中的關鍵詞及等義表達重新排序候選段落；若找不到直接支持的文字，就回答資料不足。每個有根據的回答都要顯示文件、來源網址、相關段落、相似程度與取得時間；來源網址只能連到原始網址，取得時間要顯示在連結外。同一份文件內容相近的段落只保留相似度最高的一筆引用，避免重複列出。問題若缺少影響答案的條件，例如適用年度、身分或版本，必須說明條件差異並請使用者補充，不可任意選一種規定；來源明確寫出日期、數字或期限時，必須精確回答並說明適用範圍。資料不足時清楚顯示「資料不足，無法根據目前來源回答」，不要呼叫回答模型。把問題、回答、回答狀態、花費秒數與引用寫到本機問答紀錄檔 `feedback/query_log.jsonl`。側欄使用「問答」與「問答紀錄」切換；問答紀錄用表格顯示每次對話的主要主題、題數、狀態與平均秒數。完成後執行 `python -m streamlit run rag/app.py`，確認它使用我的資料，不是範例資料，並告訴我使用了哪些文件與索引段落數。

**提示詞 05-4｜修正回答與引用品質**

> 請檢查目前的問答助手，不要重建資料或重新抓取文件。修正以下問題：同一文件的重複引用只顯示一筆；原始網址與取得時間必須分開呈現，且連結只能開啟原始網址；問題若缺少影響答案的條件，要說明需要補充什麼，不可任意猜測。加入通用的證據驗證：回答日期、數字、期限或其他精確事實前，引用段落必須直接提到同一件事；不能只因段落含有一個數字或日期就採用。以關鍵詞與等義表達輔助重新排序候選段落，但不要為特定題目或特定答案寫死規則。完成後用兩題測試：一題有明確答案的問題，以及一題缺少必要條件或資料不足的問題；確認回答、引用與提示都符合上述規則。
