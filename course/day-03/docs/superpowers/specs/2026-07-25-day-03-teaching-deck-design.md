# Day-03 當天授課簡報設計

## 目的

建立一份供 2026-08-05 現場投影授課使用的 18 張 PPT。它支援概念講解與個人跟做，讓初學者透過 Codex 的自然語言協作完成公開文本蒐集、解析、分析、本機向量檢索問答與自我測試改善。

## 受眾與使用情境

- 受眾：具基本電腦操作能力、程式初學者。
- 使用者：講師張育慈 Ruby。
- 情境：09:00–16:30 現場投影；09:00–09:30 先在課堂安裝 MarkItDown MCP、Ollama、兩個模型與 Streamlit，之後逐段操作與共同檢查。
- 範圍：簡報不取代 repo 中的提示詞與練習檔；投影片只呈現目的、下一步與檢查點。

## 投影片架構

共 18 張：

| 節點 | 投影片 | 教學目的 |
| --- | --- | --- |
| 開場與工具建置 | 1–3 | 說明今日成果、時程，以及課堂內完成工具安裝與健康檢查。 |
| 名詞橋接 | 4–6 | 解釋 MCP、MarkItDown、manifest、metadata、chunk、provenance、RAG、Ollama、JSONL。 |
| 建立範圍與蒐集 | 7–8 | 個人資料夾、統一 scope、robots／速率限制、manifest。 |
| 解析與分析 | 9–12 | MarkItDown、品質檢查、chunks、AI 分析表。 |
| 向量檢索問答 | 13–15 | 本機 embedding、支持性回答、`insufficient_evidence` 與自訂四類測試。 |
| 自我測試與收尾 | 16–18 | self-test log、改善 backlog、個人自我完成檢核。 |

## 核心名詞的教學定義

| 名詞 | 課程中的一句話定義 |
| --- | --- |
| MCP | 讓 Codex 可以呼叫外部工具的標準接頭。 |
| MarkItDown | 將已下載的 HTML、PDF、DOCX 轉成 Markdown 的解析器；不是爬蟲。 |
| manifest | 記錄資料從哪裡來、何時取得、存在哪裡的清單。 |
| chunk | 為檢索而切出、仍保有來源的一小段文本。 |
| provenance | 從答案一路回查到原始網址與時間的證據鏈。 |
| 向量檢索 | 用本機 embedding 找出最相近的 chunks；結果仍需人工核對。 |
| RAG | 先找有根據的 chunks，再讓模型回答並附引用。 |

## 固定教學訊息

- 全班從 `https://tve.yuntech.edu.tw/` 開始；僅該完整主機、最多 20 個 HTML 與 20 份附件、單一連線且至少 1 秒間隔。
- 課堂內安裝 `qwen2.5:3b` 與 `nomic-embed-text-v2-moe`；向量化與索引由提示詞封裝，學生檢查前三個 chunks、相似度與引用。
- 所有支持性回答均附文件、URL、段落位置與 `crawled_at`；不足證據不生成答案。
- 原型僅本機執行，並固定提示以原始網站最新公告為準。
- 不收件、不評分；最後由每位學生用自我檢核完成證據鏈。

## 視覺與 QA

維持深墨綠、暖米色、湖水綠與珊瑚橘的資料管線母題。每張附講者備註，且至少有一個視覺元素。產生後抽取文字、轉成圖片，檢查內容、溢出、重疊、對比與邊界；修正至少一項發現後再驗證。
