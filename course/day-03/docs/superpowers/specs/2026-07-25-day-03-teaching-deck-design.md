# Day-03 當天授課簡報設計

## 目的

建立一份供 2026-08-05 當天投影授課使用的 PPT。它要同時支援概念講解與學生跟做，讓學員理解專有名詞後，依序完成公開文本蒐集、解析、分析、可引用問答與回饋改善。

## 受眾與使用情境

- 受眾：具基本電腦操作能力、正使用 Codex 的課程學員。
- 使用者：講師張育慈 Ruby。
- 情境：09:00–16:30 現場投影；講師在每個實作區段展示提示詞、讓學生操作，並在檢查點確認產物。
- 範圍：本簡報不取代 repo 中的提示詞與練習檔；投影片只呈現每一階段的目的、可直接採取的下一步與檢查點。

## 敘事與投影片架構

採「概念頁 → 操作頁 → 檢查點」的雙層節奏，共 22 張：

| 節點 | 投影片 | 教學目的 |
| --- | --- | --- |
| 開場 | 1–3 | 說明今日成果、時程與資料管線。 |
| 名詞橋接 | 4–6 | 解釋 MCP、MarkItDown、manifest、metadata、chunk、provenance、RAG、Ollama、JSONL。 |
| 建立範圍 | 7–8 | 建立小組資料夾與 crawl scope。 |
| 蒐集 | 9–10 | 說明白名單爬取與 manifest。 |
| 解析 | 11–12 | 說明 MarkItDown MCP 的正確位置與品質檢查。 |
| 分析 | 13–14 | 產生 chunks、AI 分析表與可回溯證據。 |
| 問答 | 15–17 | 解釋 RAG、示範支持性回答與 insufficient_evidence。 |
| 回饋 | 18–19 | 由 query log 產生改善 backlog。 |
| 收尾 | 20–22 | 繳交清單、展示方式與今天的核心原則。 |

## 核心名詞的教學定義

| 名詞 | 課程中的一句話定義 | 視覺表現 |
| --- | --- | --- |
| MCP | 讓 Codex 可以呼叫外部工具的標準接頭。 | Codex 與 MarkItDown 之間的插頭。 |
| MarkItDown | 將已下載的 HTML、PDF、DOCX 轉成 Markdown 的解析器；不是爬蟲。 | 原始文件轉為可讀文字的轉換器。 |
| manifest | 記錄資料從哪裡來、何時取得、存在哪裡的清單。 | 帶有 URL、時間、檔案路徑的資料護照。 |
| metadata | 描述一份文件或一段文字的欄位。 | 文件標籤。 |
| chunk | 為檢索而切出、仍保有來源的一小段文本。 | 長文件切成可引用卡片。 |
| provenance | 從答案一路回查到原始網址與時間的證據鏈。 | 答案反向連到來源的箭頭。 |
| RAG | 先找有根據的 chunks，再讓模型回答並附引用。 | 檢索在前、生成在後的兩段流程。 |
| Ollama | 在自己的電腦上執行 `qwen2.5:3b` 的本機模型服務。 | 筆電內的模型引擎。 |
| JSONL | 每行一筆 JSON 紀錄，適合持續追加 manifest、品質報告或問答紀錄。 | 一列一張小卡的清單。 |

## 視覺設計

- 視覺母題：一條由「公開網站」流到「可引用答案」的資料管線，所有章節用同一條路徑定位。
- 色彩：深墨綠 `#163A35` 為主、暖米色 `#F4EFE6` 為底、湖水綠 `#65B8A6` 表示可進入下一步、珊瑚橘 `#E37B62` 表示停止或需檢查。
- 版型：開場與收尾深色底；概念頁採圖解或卡片；操作頁使用左側提示詞摘要、右側預期產物；檢查點以大勾選項呈現。
- 字體：標題採 Noto Sans TC Bold 或可用的思源黑體粗體；正文採 Noto Sans TC／思源黑體。標題至少 36pt，正文至少 18pt。
- 每張投影片至少一個視覺元素（流程節點、文件卡、表格、圖示或對話視窗）；不使用長段落或純文字清單。

## 關鍵投影片內容

### 名詞橋接（4–6）

先用一張「為什麼要分工」圖解：爬蟲取得檔案、MarkItDown 轉文字、RAG 用文字回答。下一張以 MCP 與 MarkItDown 為中心，特別說明「先爬取，後解析」。第三張以文件卡片、chunk 卡片與回答連線，解釋 metadata、provenance、RAG、Ollama、JSONL。

### 六段操作（7–19）

每段操作頁不貼完整提示詞，僅呈現提示詞檔名、三到五個行動指令、預期資料夾／檔案與一個停止條件。講師再引導學生開啟 repo 中對應的完整提示詞。

### RAG 示範（15–17）

用兩張並列對話畫面呈現：

1. 「最晚何時送所辦？」回答第一年第一學期結束前，並列出文件、網址、段落與 crawled_at。
2. 「資格考何時申請？」顯示 `insufficient_evidence`、不生成猜測答案，並說明要補蒐集哪一類文件。

第三張列出四類基本測試與「衝突／過期資料是進階挑戰」。

## 講師提示與驗收

- 每段檢查點清楚說出可繼續與必須停止的條件。
- 提醒學生：公開聯絡資訊必須有來源；白名單外、登入後或不足證據的內容不可猜測。
- 備援語料只在網站、下載或解析異常致使無法完成至少三筆 ready_for_analysis chunks 時啟用。
- 最後用五項繳交物和「資料可追溯性重於介面美觀」收束。

## 產物與 QA

- 產物：`slides/day-03-generative-ai-text-analysis.pptx`。
- 每張簡報附講者備註：講師要說的關鍵句與學生應完成的動作。
- 建立後以 MarkItDown 抽取文字，並轉為圖片做視覺 QA；至少執行一次修正後再驗證。
