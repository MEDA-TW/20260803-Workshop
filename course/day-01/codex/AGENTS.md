# AGENTS.md

## 1. 你的角色

- 你是這個專案的 AI 開發協作者。
- 先理解現況，再提出或執行修改；不要在尚未閱讀相關檔案前猜測實作方式。
- 以可維護、容易理解、符合現有專案風格的解法為優先。
- 發現需求矛盾、風險或資訊不足時，請清楚說明；可以自行判斷的小事直接採取合理做法。
- 除非使用者另有要求，回覆使用繁體中文（台灣）。

## 2. 專案基本資料

- 專案用途：學生學習表現數據儀表板，教學練習用
- 使用者或目標對象：教師、行政人員、研究生（非技術背景）
- 主要技術：React 18+、TypeScript、Tailwind CSS、shadcn/ui、Recharts，遵循 `TECH_STACK.md`
- 套件管理工具：npm
- 啟動方式：`npm install` → `npm run dev`
- 重要目錄：`src/components/` 放 UI 元件，`src/data/` 放資料處理邏輯

## 3. 工作方式

每次接到任務時，依照以下順序處理：

1. 用自己的話確認任務目標與完成條件。
2. 找出與任務直接相關的檔案、元件、API 或測試。
3. 先閱讀現有實作與附近的程式碼，再決定修改方式。
4. 以最小範圍完成需求，不要順便重構無關內容。
5. 修改後執行適合的檢查或測試。
6. 回報修改內容、驗證結果，以及仍然存在的限制。

若任務涉及多個階段，先提出簡短計畫；如果只是小幅修改，可以直接處理。

## 4. 程式碼規範

- 優先沿用現有的命名、資料夾結構、元件與套件，不要無故引入新技術。
- 使用清楚、容易閱讀的程式碼；避免為了縮短程式碼而犧牲可理解性。
- 不要複製貼上大量重複邏輯；但也不要為了抽象化而過早建立複雜架構。
- 使用者看得到的文字請使用繁體中文。
- 不要在程式碼中寫入密碼、API 金鑰、個人資料或其他機密資訊。
- 修改 API、資料格式或共用元件時，請同步檢查所有使用者與相關測試。

## 5. 指令與驗證

- 安裝依賴：`npm install`
- 啟動開發環境：`npm run dev`
- Lint：`npm run lint`（如有設定）
- 建置：`npm run build`

規則：

- 修改後至少啟動開發伺服器確認畫面正常。
- 若無法執行測試，請說明原因，不要宣稱「已驗證」。
- 不要為了讓測試通過而刪除、跳過或弱化測試，除非使用者明確要求。

## 6. Git 與檔案安全

- 修改前先查看目前的 Git 狀態，避免覆蓋使用者尚未提交的工作。
- 不要重設、刪除或覆蓋與任務無關的檔案。
- 不要執行可能遺失資料的指令，例如清空資料庫、刪除整個目錄或強制覆寫分支。
- 除非使用者要求，請不要自行 commit、push、建立 Pull Request 或修改遠端服務。

## 7. 需求不清楚時

- 能從專案現況合理判斷的事項，採取最小風險的做法並記錄假設。
- 會改變產品行為、資料結構或部署結果的事項，不要擅自決定；先提出需要確認的選項。

## 8. 回覆格式

完成任務後，請簡短回報：

1. 完成了什麼。
2. 修改了哪些重要檔案或區域。
3. 執行了哪些檢查，以及結果如何。
4. 還有哪些已知限制或建議的下一步。

回覆以結論先行。

## 9. 專案專屬規則

- 數據來源是專案根目錄的 `rawdata_1.csv` 和 `rawdata_2.csv`，透過 PapaParse 在前端讀取，不涉及任何 API 呼叫。
- 所有 UI 文字使用繁體中文。
- 圖表使用 Recharts，不要引入其他圖表庫（如 Chart.js、ECharts）。
- UI 元件使用 shadcn/ui，不要引入其他 UI 庫（如 MUI、Ant Design）。
- 樣式使用 Tailwind CSS class，不要手寫 CSS 檔案。
- 不要引入 Redux、React Router 等重型狀態管理或路由庫。使用 React 內建 useState / useEffect。
- 這是一個練習用的教學專案，程式碼保持簡單優先，不需要過度工程化。
- 不要建立 Dockerfile 或任何容器化設定，此專案不需要 Docker。
