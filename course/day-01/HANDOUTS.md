# A4 隨身卡

建議雙面列印。正面是方法，背面是四格提示詞演練。

## 正面｜今天帶得走的方法

### 提示詞四要素

1. **目標 Goal**：最後要完成什麼？
2. **背景 Context**：要參考哪些資料、檔案與規則？
3. **輸出 Output**：成品長什麼樣，怎麼知道完成？
4. **邊界 Boundaries**：什麼不能做，什麼要先問？

```text
好提示詞
＝ 目標
＋ 必要背景
＋ 可驗收輸出
＋ 關鍵邊界
```

### Vibe Coding 四條心法

1. 說結果，不微管理步驟。
2. 給背景，不期待 AI 自己猜。
3. 定義驗收標準，信任但驗證。
4. 迭代是常態，不是失敗。

### Agent 三大要素

- **LLM**：大腦與推理。
- **Tools／Skills**：雙手與 SOP。
- **Memory**：短期對話＋長期專案文件。

### 先看任務，再選 Agent

- 建立或修改程式：Codex、Claude Code
- 長期個人助理：Hermes Agent、OpenClaw
- 管理多個 Agent：LobeHub

> Agent 多不等於比較厲害；先看任務、介面、資料位置與維護成本。

### 三個檔名

- `README.md`：今天要做什麼。
- `TECH_STACK.md`：用什麼做。
- `AGENTS.md`：Agent 要怎麼做事。

### 救援兩招

> 剛剛的修改讓畫面變差了，請只還原本輪變更。

> 以下是完整錯誤訊息。請說明根因、做最小修正，修正後重新檢查。

### 責任邊界

> 你可以把手放開，但不能把眼睛閉上。

不貼真實姓名、學號、成績；數字與引用回原始來源核對；對外發布前由人覆核。

# 提示詞正反例與救援模板

## 太籠統

> 幫我做一個成績網頁。

問題：不知道使用者、資料、畫面內容、完成標準與限制。

改寫：

> 目標：做一個給導師查看班級成績的響應式卡片區。<br>
> 背景：沿用目前 React 專案與既有 Card，資料先用假資料。<br>
> 輸出：顯示平均分數、最高分、待關注人數；桌機三欄、手機一欄。<br>
> 邊界：不要加入真實學生資料、不要安裝套件。

## 過度微管理

> 先建立 A.tsx，再新增 B 函式，第 12 行放一個 div，使用這 18 個 class……

問題：把 Agent 當打字員，步驟綁死；現有結構不同就容易失敗。

改寫：

> 在現有首頁加入三張響應式成績摘要卡。沿用專案規則與既有 Card；清楚區分主要數字與補充說明，手機不溢出。不要安裝套件，完成後跑 build。

## 建立元件模板

> 目標：新增【元件用途】。<br>
> 背景：先讀 `TECH_STACK.md` 與現有相近元件。<br>
> 輸出：包含【內容】與【互動】，並通過【驗收方式】。<br>
> 邊界：不要安裝套件、不要刪除既有功能。

## 除錯模板

> 以下是完整錯誤訊息：<br>
> 【貼上完整內容】<br>
> 請先用一句話說明根因，再做最小修正。不要安裝套件或更換技術棧，修正後重跑原本失敗的檢查。

## 還原模板

> 剛剛的修改讓畫面變差了。請只還原本輪變更，保留更早已完成並 commit 的功能。完成後告訴我還原了哪些檔案。

## 驗收模板

> 請不要新增功能。只檢查目前成品是否符合：內容正確、手機不破版、資料正確、build 通過。發現問題就做最小修正，最後列出我應在瀏覽器確認的三件事。
