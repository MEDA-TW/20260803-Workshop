# 分支管理策略

> 初學者友善 | 約 10 分鐘

## 你可能遇過這些問題

你 Clone 了專案的 Repo，直接在 main branch 上改了幾個檔案，準備提交時才發現：其他人也在改同一個檔案，而且改的內容跟你不一樣。更糟糕的是，你的變更破壞了原本可以正常運作的功能。

這些問題的根源在於：**main branch 是所有人的共用基礎，不應該直接在上面開發。**

## 完成後你會理解

- 為什麼需要分支
- main branch 和 feature branch 的差異
- 如何在自己的分支上安心開發

---

## 分支是什麼？

可以把 main branch 想像成一本書的正式出版版本。每次有人要新增章節或修改內容，不是直接在正式版上改，而是先在旁邊的草稿本上寫，寫完確認沒問題後再合併回去。

在 Git 中，這個「草稿本」就是 **branch（分支）**。

```
main        ────●────●────●────●────●
                           \
feature/login     ──────────●────●
```

- **main branch**：穩定版本，所有已驗證的變更才會合併到這裡
- **feature branch**：開發用的分支，在這裡自由修改，完成後透過 PR 合併回 main

## 分支保護規則

實驗室的 Repo 設有分支保護規則，main branch 的保護機制如下：

| 規則 | 說明 |
|:-----|:-----|
| 不允許直接推送 | 必須透過 PR 才能合併到 main |
| 至少一位審查者批准 | PR 需要有人看過才會被合併 |
| 通過 CI 檢查 | 自動化測試必須通過 |

這些規則確保 main branch 始終保持可用狀態。即使有人提交了有問題的變更，也會在 PR 階段被攔下。

## 正確的工作流程

### 從 Repo 建立專案

**不要直接 Clone main branch 開始改。** 正確的流程是：

1. Clone Repo 到本地
2. 建立自己的分支
3. 在自己的分支上開發
4. 完成後推送並建立 PR

### 使用 Git 指令操作

```bash
# 1. Clone Repo
git clone <Repo URL>

# 2. 建立並切換到新分支
git checkout -b feat/你的功能名稱

# 3. 開發完成後，提交變更
git add .
git commit -m "新增功能說明"

# 4. 推送到遠端
git push origin feat/你的功能名稱

# 5. 到 GitHub 上建立 PR
```

### 使用 GitHub Desktop 操作

1. 點選 `File > Clone Repository` 下載 Repo
2. 點選左上角的 `Branch` > `New Branch`
3. 輸入分支名稱（遵循命名規範），點選 `Create Branch`
4. 開發完成後，點選 `Commit to <你的分支名稱>`
5. 點選 `Push origin` 上傳變更
6. 點選 `Create Pull Request` 建立 PR

## 常見問題

**Q：如果我想同時開發兩個功能怎麼辦？**

為每個功能建立各自的分支。一個功能完成並合併後，再開始下一個。不要在同一個分支上混雜多個不相關的功能。

**Q：不小心在 main branch 上改了東西怎麼辦？**

如果還沒有推送，可以用 `git stash` 暫存變更，切到新分支後再取出。如果已經推送了，趕快建立一個 PR 把變更合併，並在說明中標註這是意外提交。

**Q：main branch 和 production 有什麼差異？**

有些團隊會同時維護 `main`（開發用）和 `production`（正式環境）兩個分支。實驗室目前以 `main` 為主，如果未來有正式環境需求，會再另行規範。
