# PR 流程與 Code Review

> 中等 | 約 15 分鐘

## 你可能遇過這些問題

開發完成了，變更也推送到了自己的分支，但不知道下一步該怎麼做。或者，PR 建好了卻不知道要寫什麼說明，審查者也不清楚你改了什麼。

PR（Pull Request）是團隊協作的核心。透過 PR，你的變更會被放在所有人面前，經過檢查後才會合併到 main branch。這不是多此一舉，而是保護團隊的最後一道防線。

## 完成後你會理解

- 如何建立一個格式完整的 PR
- Code Review 的流程與禮儀
- PR 被要求修改時該怎麼處理

---

## 完整流程

```
開發完成
   │
   ▼
推送分支到遠端
   │
   ▼
建立 PR（填寫說明）
   │
   ▼
指派審查者
   │
   ▼
審查者進行 Code Review
   │
   ├── 通過 ──→ 合併到 main
   │
   └── 需修改 ──→ 修改後重新推送 ──→ 再次審查
```

---

## Step 1：推送分支到遠端

開發完成後，將你的分支推送到 GitHub：

**Git 指令：**

```bash
git push origin feat/你的功能名稱
```

**GitHub Desktop：**

點選 `Push origin` 按鈕即可。

---

## Step 2：建立 PR

### 在 GitHub 網頁上建立

1. 進入 Repo 的 GitHub 頁面
2. 點選「Compare & pull request」按鈕（如果有的話）
3. 或點選「Pull requests」分頁 > 「New pull request」

### 填寫 PR 說明

PR 說明是審查者最重要的參考依據，請務必填寫清楚：

**標題格式：**

```
<類型> <簡述>
```

範例：
- `feat 新增使用者登入功能`
- `fix 修正表單送出時的空值錯誤`
- `docs 更新 API 文件`

**說明內容建議包含：**

```markdown
## 變更內容
- 新增了什麼功能或修正了什麼問題
- 為什麼要做這個變更

## 測試方式
- 如何驗證這個變更是正確的
- 執行了哪些測試

## 截圖（如適用）
- 如果有畫面變更，附上截圖
```

---

## Step 3：指派審查者

建立 PR 徉，在右側「Reviewers」區域點選齒輪圖示，選擇要審查的人。

- 一般功能變更：指派該 Repo 的負責人
- 大型變更或架構調整：建議指派多位熟悉該模組的成員

---

## Step 4：Code Review

審查者會針對以下幾點進行檢查：

| 檢查項目 | 說明 |
|:---------|:-----|
| 程式碼品質 | 命名是否清楚、邏輯是否合理 |
| 功能正確性 | 變更是否達到預期目的 |
| 潛在問題 | 是否有邊界情況未處理、是否影響其他功能 |
| 測試覆蓋 | 有沒有相應的測試 |

### 審查者的工作

- 閱讀 PR 說明和程式碼變更
- 留下建設性的回饋（指出問題所在，而不只是說「不好」）
- 通過或要求修改

### 開發者收到回饋後

1. 閱讀審查意見
2. 在本地修改後推送（不需要建立新的 PR，同一個分支的變更會自動更新）
3. 在 PR 留言回覆說明做了哪些調整
4. 等待再次審查

---

## Step 5：合併 PR

PR 通過審查後，由以下人員進行合併：

- Repo 負責人
- 或被指派的審查者

合併後，GitHub 會自動刪除已合併的分支（建議在 Repo 設定中開啟此功能）。

---

## PR 禮儀

### 作為開發者

- **PR 說明要寫清楚**：不要只寫「改了一些東西」。審查者沒時間猜你在做什麼。
- **變更要小而集中**：一個 PR 只做一件事。如果發現改了很多東西，考慮拆成多個 PR。
- **不要囤積變更**：開發到一個段落就提交，不要等到全部做完才一次提交數百行變更。

### 作為審查者

- **及時回覆**：收到 PR 審查通知後，盡量在一天內完成。
- **對事不對人**：指出問題時描述程式碼的問題，而不是批評寫程式碼的人。
- **區分嚴重程度**：哪些是必須修改的、哪些是建議改進的，要標示清楚。

## 常見問題

**Q：PR 一直沒有人審查怎麼辦？**

先在實驗室的溝通群組中提醒一下負責人。如果負責人不在，可以請其他有經驗的成員協助審查。

**Q：審查者說要改，但我不確定怎麼改怎麼辦？**

直接在 PR 留言中回問，說清楚你的疑慮。Code Review 是學習的機會，不用怕問問題。

**Q：我的變更跟 main branch 有衝突怎麼辦？**

在本地將 main branch 的最新變更合併到你的分支：

```bash
git checkout main
git pull origin main
git checkout feat/你的功能名稱
git merge main
```

解決衝突後重新推送。GitHub Desktop 上可以透過 `Branch > Update from main` 達成同樣效果。

**Q：什麼時候可以自己合併 PR？**

實驗室的規範是：自己的 PR 不應該自己合併。即使你有權限，也請等待他人審查通過後再合併。這是為了確保至少有兩個人看過同一份變更。
